## Vision

### 10x Check
A CFO who lives in your house. Sees everything. Saves $50-200/month. One screenshot makes a friend say "I need that."

Concrete:
- "You spent $847 on DoorDash this quarter. 4x last year. Every Wednesday after 9pm."
- "I found $67/mo in subscriptions you haven't touched in 90 days."
- "This $340 charge is 3σ off your pattern. Block?"
- "Based on cash flow, you could safely sweep $127/mo to rainy-day savings."
- Proactive Month in Review on statement upload.

### Platonic Ideal
Privacy-first personal CFO in one box at home. Zero cloud. Saves real money. Makes friends say "holy shit."

### Strategic Direction — REVISED
**Approach A' (hybrid):** Build insights on the **existing 5-service architecture**. Ship to 3-5 real users (yourself + friends/family). Validate value first. Refactor to monolith ONLY after the insights prove they actually save people money.

**Business model:** Reframed as **open-source personal project with donate button.** Drop BUSINESS.md's $29 commercial framing. If organic adoption proves PMF, revisit commercial model. Outside voice was right: premature commercialization masks whether the product is actually valuable.

**Sequence:**
1. **Weekend spike:** LLM hallucination eval (next 2 days)
2. **Phase 1:** Real Insights Engine + Month in Review on current 5-service stack (2-3 weeks)
3. **Phase 2:** Subscription Auditor (1-2 weeks)
4. **Validation gate:** 3-5 users using it for 4+ weeks. Metric: did the app flag ≥1 real money-saving thing per user per month?
5. **Phase 3 (IF validation passes):** Fraud + Savings + refactor to monolith + packaging
6. **Phase 3 (IF validation fails):** Stop. Repurpose as personal tool. Open-source as-is.

### Outside Voice Concessions Applied

- **Sequencing flipped.** Insights on current stack first. Validate before refactor.
- **LLM eval sequenced first.** Spike before more planning or building.
- **Business model dropped.** OSS + donate, not $29 commercial. BUSINESS.md stays as "aspirational" / "not current direction."
- **Hallucination bar widened.** Includes merchants + dates + categories, not just numbers. If eval #0 shows this is impossible at 1B, fall back to rules-rendered templates for insights (no LLM narration for numbers).
- **Validation gate added.** 3-5 real users × 4 weeks × ≥1 saved-money moment per user per month = the bar. Below that, stop.

## Phase Definitions of Done

### Phase 0 — Eval Spike (this weekend)

**Deliverable:** `evals/insight_hallucination/` directory with:
- 30 fixture transactions (real shape, synthetic merchant/amount/date)
- 15 questions spanning: total by category, count by merchant, date-range sums, trend direction, comparison
- 5 Month-in-Review-style prompts
- Manual-graded results: numeric accuracy %, merchant accuracy %, date accuracy %, category accuracy %

**Success criteria:** ≥95% numeric accuracy, ≥90% merchant accuracy, ≥95% date accuracy on llama3.2:1b.

**If failed:** Pivot to rules-rendered templates for all insight text. LLM only powers Q&A chat (where hallucination is visible in dialogue, not authoritative statements).

### Phase 1 — Insights + Month in Review (on current stack)

**Deliverable:**
- 5 rule classes shipped in `services/sophia/`: category-shift (>20% vs 90d), new-recurring-merchant, day-of-week cluster, price-escalation, anomaly-cluster
- Month in Review page + triggered on statement upload
- Each insight: finding, evidence transactions (linked), confidence, dismiss
- README + ROADMAP corrected to describe current architecture

**Success:** your own dogfooding detects ≥3 real patterns in your 90-day history you didn't already know.

### Phase 2 — Subscription Auditor (on current stack)

**Deliverable:**
- Recurring charge detection (amount ±5%, cadence ±3d)
- Subscription list UI with kill action + curated cancel URL registry (~50 services)
- First-time surface: "Found N recurring charges totaling $X/mo"

**Success:** you identify ≥1 subscription to kill from your own data.

### Validation Gate (after Phase 2)

**Recruit 3-5 people (friends, family, privacy-community):**
- Install on their Jetson or cloud VM
- 4-week usage period
- Weekly check-in

**Metric:** ≥60% of users flag ≥1 saved-money moment per month (subscription killed, fraud caught, spending-cut insight applied). Below threshold: stop building.

### Phase 3 (validation-passed): Fraud + Savings + Monolith + Packaging

Unchanged from prior plan. Gate it behind validation.

## Critical Constraints

1. **Data cadence is monthly.** Statement-triggered proactive features, not clock-triggered.
2. **Small local models hallucinate broadly.** Not just numbers — merchants, dates, categories. Phase 0 eval gates the entire plan.
3. **Doc drift is severe.** Fix in Phase 1.
4. **Distribution is NOT existential until validation.** Dropped from critical constraint list.
5. **Ollama friction kills conversions.** Becomes material only if Approach B ever re-activates post-validation.
6. **SQLite corruption / backup story.** Becomes material post-refactor. Not blocking.
7. **Solo-dev burnout.** Scope defense. Validation gate protects against over-investment.

3. **Backup story** — deferred until refactor.
4. **Multi-user support** — deferred until validation.
5. **Telemetry / crash reporting** — deferred; OSS + public repo = users can open issues.
